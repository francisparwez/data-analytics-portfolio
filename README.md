🔗 **[View Project on GitHub](https://github.com/francisparwez/vehicle-service-repair-data-pipeline)**

**Platform:** Microsoft SQL Server / T-SQL\
**Architecture:** Raw → Staging → Analytics → ML

An end-to-end SQL Server data engineering and analytics project that takes raw vehicle service and repair data from CSV ingestion through **data profiling, quality auditing, cleansing, normalization, feature
engineering, exploratory analysis, validation, and ML-ready dataset publication**.

The project uses four logical schemas:

- `raw` --- preserves the original source representation
- `stg` --- contains cleaned and standardized data
- `analytics` --- contains normalized and analytical structures
- `ml` --- contains engineered features and the published ML-ready dataset

**Key work demonstrated:**

- SQL Server database and layered schema architecture
- Raw CSV ingestion using `BULK INSERT`
- Raw-layer preservation and data lineage
- Data profiling and data-quality auditing
- Missing-value, duplicate, and invalid-value analysis
- Reference-data mapping
- Data cleansing and standardization
- Raw-to-staging transformation
- Customer ID data-type validation and conversion
- Vehicle manufacturer, model, and type standardization
- Service-history normalization using `STRING_SPLIT()` and
  `CROSS APPLY()`
- Relational decomposition of multi-valued service-history data
- Customer-level analytical feature engineering
- Service-count and multi-service indicators
- Problem and solution categorization
- Exploratory data analysis
- Cross-layer and customer-level validation
- ML schema and table creation
- ML dataset publication and readiness validation

**Pipeline:**

```text
Kaggle CSV
    ↓
RAW Layer
    ↓
Data Profiling & Quality Audit
    ↓
Reference Mapping
    ↓
STG Layer
    ↓
Cleaning & Standardization
    ↓
Normalization
    ↓
ANALYTICS Layer
    ↓
Feature Engineering
    ↓
Exploratory Data Analysis
    ↓
Data Validation
    ↓
ML Layer
    ↓
Validated ML-Ready Dataset
```

**Project status:** Phase 11 complete --- ML-ready dataset publication and validation completed. Final documentation remains as the next project stage.

**Repository:** [Vehicle Service & Repair Data Pipeline](https://github.com/francisparwez/vehicle-service-repair-data-pipeline)

## 📌 Portfolio Philosophy

I approach analytics as more than simply creating charts.

A strong analytical project should answer four questions:

1.  **Is the data reliable?**
2.  **Was the data transformed correctly?**
3.  **Does the analysis answer a meaningful question?**
4.  **Can another person understand and reproduce the work?**

That is why my projects place emphasis on **data quality, transparent transformations, analytical reasoning and documentation** alongside the
final results.
